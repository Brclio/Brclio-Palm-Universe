# 当前交互顺序与控制器接口

依据：原片关键帧、`source-reaudit-v2.md`，以及前两次切换的新审阅 `flip-gesture-audit-v3.md`。可确认的是手型、动作顺序、物体位置与画面变化；原始源代码和识别参数未知。首页默认鼠标完整流程，摄像头共用同一顺序控制器，并提供当前步骤的原片示范。

舞台和画布铺满浏览器窗口，控件悬浮覆盖。摄像头完整保留实际 `videoWidth / videoHeight` 比例，通过 `contain` 居中等比显示；逻辑画幅是镜头完整画面，不含窗口比例差异留下的边区。骨架、天体、月相和空间判定使用同一逻辑坐标，再整体平移到窗口内的显示矩形。鼠标模式直接使用完整窗口，不再固定16:9。

## 顺序与响应

| 原片时间附近 | 手势 | 响应与状态 |
|---|---|---|
| 16.1秒 | 收拢四根长指握拳，拇指可外伸 | 召出按参考样式建模的立体金星，随后固定：`idle → star` |
| 17.2秒 | 松手，在星星附近短促翻腕甩手；镜像画面左→右 | 星向右退出、太阳由左补入：`star → sun` |
| 18.4秒 | 回收手腕恢复预备方向，拇食指伸出，再做一次同向翻腕甩手 | 太阳换月球：`sun → moon` |
| 19.5–21.4秒 | 月球附近C形夹取，夹小后向右移动 | 抓取后才跟手，按开口连续缩放：`moon → moonHeld` |
| 21.4秒 | 伸直食指并张开拇指释放 | 从最后持球点向右微移约.03画宽，约.6秒放大后固定：`moonHeld → moonReleased` |
| 23.03秒 | 五指张掌向左扫 | 触发后五个月相自主依次展开，右端满月及横排高度固定：`moonReleased → phases` |
| 25秒附近 | 回到最右端满月，C形夹取 | 小月球跟手，其他月相消退：`phases → phaseHeld` |
| 26.7秒 | 夹持向左上举起，再张开拇食指成L形 | 月球向手左下放大为黑胶唱片，唱臂与唱头保持独立形状：`phaseHeld → pan` |
| 33秒附近 | 唱片旁先握拳，再快速张开五指 | 只触发一次爆散，保持空场直到重来：`pan → burst` |

`pan` 是兼容已有数据的内部标识，用户看到的是黑胶唱片。底部流程进度不可跳步。静止V手势、反向回手、远处甩手、未抓球就抬指、唱片旁仅张掌都不能替代上述动作。月相仅由左扫触发，其后按动画进度展开，不要求手持续拖完整排。

表中方向按默认镜像预览描述。前两次切换遵循用户的真人右→左动作契约：镜像预览中 `switchDirection = +1`，非镜像预览中为 `−1`；视频、关键点和换场动画保持一致。切换镜像设置重置流程，避免旧坐标历史误触。

## 翻腕与掌尺度

摄像头的星→日→月使用腕到食指尖的局部方向、相对横移、速度与天体邻域共同判断。当前初值是：在最长480毫秒窗口内，方向转动至少0.55弧度，相对腕的指尖横移超过0.55掌尺度，指尖速度超过每秒2.4掌尺度；有效转动需跨至少两个变化区间、持续至少60毫秒。指尖还需实际向目标方向移动，避免仅移动腕点形成伪旋转。它不是要求完整180°翻面，也不要求掌心横移固定的 `.13×画宽`。

原片第一次为较完整开掌，第二次主要伸出拇食指，故不要求所有指头伸直。通过掌/指尖扫掠段及腕到指尖段检查是否接近天体，容差使用实际球体半径加掌尺度余量；无需精确穿过球心。每次只推进一个阶段，回腕使局部指向回摆至少0.5掌尺度、并超过430毫秒冷却后，才允许下一次甩动。纯平移、缓慢转腕、反向回手和单帧跳点均不能替代该动作。

掌尺度优先使用检测层平滑后的值：在原始镜头比例下计算腕到中指根部长度与掌宽的平均值，并换算为画宽单位；仅新采集帧推进约55毫秒时间常数的平滑。首次召星据此设定主体半径，并限制在画幅基准尺寸的合理范围；随后锁定该半径，窗口缩放只等比调整。抓取与甩动的邻域同样使用实际主体半径及掌尺度，减少远近镜头与横竖画幅造成的偏差。

唱片音乐绑定显现事件：初次输入只静默解锁 AudioContext，歌曲通道在所有前置阶段不创建播放节点、歌曲时间为0。`pan` 绘制出唱片后，`onRecordVisible` 才调用 `RecordAudio.activate()` 从头播放《茶花开了》。暂停/恢复同时控制三维盘体和程序光带的独立播放时钟；爆散用350毫秒淡出，重置与切换输入停止并归零。前置阶段替换曲目不会绕过此门控。

操作音效由 `InteractionAudio` 在共享 AudioContext 上通过独立增益播放：`star/sun/moon/moonHeld/moonReleased/phases/phaseHeld/burst` 的状态跃迁各触发一次对应短声，`pan` 则等实际画出唱片后才触发成形声。跟踪、提示文字或同一状态内每帧更新不重播；迟到超过250毫秒、状态已经切换、重来、静音或打开原片对照后的待解码事件被丢弃。音效可独立关闭，歌曲暂停不关闭音效。音效素材来源与非无损分离的限制见 `sfx-source-audit.md`。

鼠标按住对应收拢或夹持、松开对应张手、向右划过天体模拟甩手；摄像头才使用真实转腕和位置。`source: 'camera'` 走翻腕判断，鼠标或未提供 `source` 的旧兼容输入保留横移模拟。鼠标是交互排练，不是用鼠标证明真人手势已全部验证。

## 公共API

`public/gesture-sequence.js` 无DOM、摄像头或渲染依赖，导出 `GestureSequence`、默认同名类和 `SEQUENCE_DEFAULTS`。

```js
import { GestureSequence } from './gesture-sequence.js';
const sequence = new GestureSequence({ onEvent(event) {}, thresholds: {} });
const observed = sequence.update(handOrNull, captureSeconds, receivedSeconds);
const animated = sequence.tick(wallSeconds);
const restarted = sequence.reset(wallSeconds);
```

时间单位为秒，采集与接收时间共用同一个时钟原点。`update` 只提交新观察；第二个参数是视频帧采集时刻，第三个参数是结果接收时刻，省略时默认等于采集时刻以兼容鼠标和旧调用。`null` 表示没有可靠手部输入。有效观察的采集时间按序递增，手势停留、速度和冷却使用采集时间；跟踪是否中断则依据收到新观察的间隙，避免将稳定存在的推理延迟误判为丢手。`tick` 和视觉动画使用当前墙钟时间，画面时钟不倒退。不能逐渲染帧反复提交同一缓存手势，否则会伪造连续手势证据。

输入示意：

```js
{
  source: 'camera', handId,
  wrist: { x, y }, palm: { x, y }, index: { x, y }, thumb: { x, y },
  pinchCenter: { x, y },
  aspectRatio,     // 镜头逻辑画幅宽/高，不含窗口边区
  handSize,        // 平滑后的掌尺度，按镜头画宽归一化
  orbRadius,       // 实际绘制主体半径，按逻辑画宽归一化
  switchDirection,// 默认镜像 +1；非镜像 -1，仅前两次切换
  pinch, pinchStrength, openPalm, fist, pointing, victory, spread,
  fingerStates: { thumb, index, middle, ring, pinky }
}
```

坐标为镜头逻辑画幅中的0–1归一化坐标：右为x增加，上为y减小。摄像头未镜像的模型坐标先同步映射为预览方向，再由渲染器整体放入窗口的 `contain` 矩形，没有裁切补偿或边区偏移混入手势输入。距离使用 `hypot(dx, dy/aspectRatio)`，角度也先校正宽高比；不能直接把不同宽高比例下的 `hypot(dx,dy)` 当掌尺度。检测层没有提供稳定掌尺度时，回退为经过上述比例校正的腕到中指根部长度。

| 快照字段 | 含义 |
|---|---|
| `stage` / `mode` / `visible` | 当前顺序状态、绘制模式、是否显示主体。`phaseHeld` 使用 `moon` 模式并保留消退月相。 |
| `target` / `scale` | 当前或动画结束后的主体坐标、缩放；握持时才随指间点移动。 |
| `held` / `tracked` | 是否握持、是否有有效近期手部观察。 |
| `releaseOrigin` / `releaseTarget` / `releaseProgress` / `releaseScale` | 初次放球起点、最终目标、0–1恢复进度及释放前尺寸，供渲染器执行右移放大。 |
| `phaseAnchor` / `phaseSpan` / `phaseProgress` | 右端满月坐标、最大展开跨度、0–1动画进度；抓取后进度随消退动画下降。 |
| `panOrigin` / `panProgress` | 高举松开时的指间点、唱片形成进度；最终位置由释放点与掌长推导。 |
| `burst` / `burstTarget` | 当次更新的爆散脉冲与起点，下一次更新清除脉冲。 |
| `interaction` / `hint` / `time` | 操作状态、步骤提示、当前时间。 |

事件类型为 `stage`、`mode`、`burst`，携带当前状态、模式、时间和位置；切换事件另含先前状态。`reset` 返回空场快照，调用方同时清空粒子和画面过渡。

## 跟踪中断与验收范围

检测层用相邻观察的掌心位置建立稳定 `hand.id`，左右手标签只作弱提示；模型输出顺序变化或翻腕时标签变化不会直接替换身份。主手按 id 保持，短暂丢失时不立即让另一只手接管；约400毫秒后才允许重新选择。缺失手的历史只保留用于身份关联，不当作新检测结果发出。控制器收到不同 `handId` 时清空旧动作历史，防止把两只手拼成一次甩动。

场景保留采集时间和到达时间的区别，丢弃重复/倒序结果、超过180毫秒的结果以及明显来自未来的时间戳。仅同一结果的重复绘制调用 `tick`；新结果才调用 `update`。约150毫秒以内的短暂漏检可保留真正观测过的翻腕/横挥点；更长中断清除动作历史。持续收到新观察时，不把例如160毫秒的固定推理延迟当成150毫秒的跟踪中断。任意漏检清除稳定手势计时，握持中长中断会让物体停住，必须在原位置附近重新夹取。已启动的释放恢复、月相、唱片形成等视觉动画可以继续，`tick` 不触发新抓取、释放或爆散。

现行规则报告为 `revision-gesture-validation.json`，浏览器报告为 `revision-browser-validation.json`。后者包含真实鼠标事件和明确标注的摄像头模型测试替身，没有操作真实摄像头。
