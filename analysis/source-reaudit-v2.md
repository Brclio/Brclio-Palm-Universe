# 原片手势、物体位置与动画复核 v2

日期：2026-10-17。只读复核基于原片提取的连续帧、原生尺寸 `reference-native/04–10.png`、`public/gesture-sequence.js` 和 `public/scene.js`。本记录不把构造手部输入的单元测试当成原片一致性证据。代码正在并行修订，下文“审阅时”描述的是本轮检查到的实现，最终状态以代码为准。

## 本轮纠正的旧判断

1. 后半段的物体是有唱臂、唱头、唱片纹槽的黑胶唱片，中心嵌月球，不是锅。内部 `pan` 状态名不影响外观语义，用户文案不能再称“锅”。
2. 第一次释放月球并不要求先完全张开五指。643 帧仍是小 C 形；645 帧食指已经伸直、拇指分开，其余长指仍弯曲，月球已经开始恢复尺寸。之后手才逐渐张开并准备向左扫。
3. 月相不是逐帧按手拖动距离展开。左扫触发后，新月相继续自行展开，手停住后动画仍完成。原片最早暗月轮廓在约 692–693 帧，而不是旧报告的 703–704 帧。
4. 第一次释放后，月球不是严格锁在最后夹持中心：它在恢复尺寸的同时向右平移约 38 个原生像素，随后固定。不能把这个小位移解释成仍然跟随手指。

### 扫球空间门槛

手型判断不能代替轨迹接触。可保留当前掌心右移方向、距离和速度门槛，再让掌心、食指尖、拇指尖三条相邻观测轨迹至少一条与物体区域接触；有全部21点时也可用手指骨架段的扫掠区域。

建议初值：轨迹到球心的屏幕物理距离 `hypot(dx,dy/aspectRatio)` 不超过 `max(.05, handSize*.65)`，结合一次完整向右跨越。这里的 `handSize` 必须是 width-normalized 物理距离（dy/aspect），旧 `source-gesture-replay.json` 的输入 handSize 采用未经宽高校正的 normalized 直线距离，直接重放会高估掌长。

原片 515 帧掌心 y≈.825、球心 y≈.755，指尖区域已扫过球。若只以掌心 y 是否落在很窄的球高范围判定，会错误拒绝原片手势。553 帧同样如此。建议保留少量空间宽容，但增加“远处横挥不触发”的真实反例。

### 第一次松开与 C 形尺寸

由原帧重新识别的开口比值（已经按 16:9 纠正）是：643 帧 `.462×掌长`、645 帧 `.805×掌长`、647 帧 `.930×掌长`。643→645 同时发生食指从弯曲到伸直。建议在已经夹小的前提下增加：`index` 伸直、非 pinch、pinchStrength≤.18、开口≥.75掌长且≥历史最小开口的1.6倍，可作为释放证据；采用短稳定门槛防单帧误判。

尺寸建议单独校准 C 形可见开口，例：开口比 `.38–.78` 映射约 `.12–1` 的缩放范围，避免要求实际接触才变小。这只是可供真人试验的初值。烘焙特效遮挡会导致原帧识别的开口、fingerStates 和 pinchStrength 抖动，不能只把这些模型数字当成原片真实手指几何。

## 验证边界

本轮直接查看了上述动作边界和连续帧，未声称人工逐张检查1193帧。原片特效已经遮住手的部分区域，现成模型的原片重放存在长漏检；重新计算物理手长后，全程重放仍会在夹持移动的漏检处进入重新抓取状态。这不能证明真实摄像头一定失败，也不能证明真实摄像头已经完整通过。

需要分开记录：原片可见手型和图形对齐、控制规则回归、未烘焙特效的真人摄像头完整演示。这三者互相补充，不应以其中一项代替另一项。
